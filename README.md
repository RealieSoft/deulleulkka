# 들를까 (deulleulkka)

Pleos Connect 차량용 앱 "들를까"의 판단 엔진과, 에뮬레이터에서 SDK 동작을 확인한 코드입니다.

들를까는 주차 중에 "가 볼 곳"으로 찜해 둔 장소가 가는 길 근처에 있을 때, 운전에 방해되지 않는 순간을 골라 한 번 묻고, 수락하면 내비게이션 경유지로 넣습니다. 이 저장소의 중심은 "지금 물어도 되는가"를 정하는 판단 엔진입니다.

## 구성

| 경로 | 내용 |
|---|---|
| `engine/` | Android에 기대지 않는 순수 Kotlin 판단 엔진 |
| `engine/.../MomentJudge.kt` | 안전 → 자격 → 가치 → 빈도 순서로 보고, 처음 막힌 곳에서 멈춤. 본 것과 결과를 줄마다 남겨 "왜 그때 물었는지" 화면에 그대로 씀 |
| `engine/.../DetourEstimator.kt` | 우회 시간 어림: 더 가야 하는 직선거리 × 도로 보정값 ÷ 내비게이션의 남은 거리·시간으로 구한 평균 속도 |
| `engine/.../RoadFactorCalibrator.kt` | 경유지를 넣은 뒤 내비게이션이 다시 계산한 값으로 도로 보정값(출발값 1.3)을 그 차에 맞춤. 최근 10번까지의 가운데값, 1.0~2.5 |
| `engine/.../AskHistory.kt` | 묻고 답한 기록("다음에"는 30일 쉼, 답 없이 두 번 닫히면 "다음에"로 봄). 기기 안에만 둠 |
| `engine/.../replay/` | 시나리오 재생기. 출력은 `docs/replay-output.txt` |
| `app/` | Pleos Connect 에뮬레이터에서 내비게이션(NaviHelper 3.0.5)과 위치(FusedLocation 1.1.3) SDK를 확인한 화면 두 개 |

## 실행

JDK 17이 필요합니다. 엔진 테스트와 재생기는 Android SDK 없이 돌아갑니다. `app/`을 빌드할 때만 Android SDK(`ANDROID_HOME` 또는 `local.properties`의 `sdk.dir`)가 필요합니다.

```
./gradlew :engine:test   # 테스트 50개
./gradlew :engine:run    # 시나리오 재생
```

테스트 50개 가운데 42개는 판단 표·시나리오·보정·기록을 옮긴 단위 테스트이고, 8개는 [kotest-property](https://github.com/kotest/kotest)(테스트 전용)로 무작위 상황 1만 개씩에서 안전 규칙을 확인합니다.

- 목적지가 회사면 다른 값이 무엇이든 묻지 않는다
- 통화 중이거나 안내 음성이 나오면 말을 걸지 않는다
- 확인할 수 없는 안전 신호가 하나라도 있으면 완전히 멈춘 때만 묻는다
- 이미 경유지가 있거나 잔량이 기준 아래면 묻지 않는다
- 처음 막힌 곳에서 멈추고 그 뒤 항목은 보지 않는다
- 보정값이 커져도 묻지 않던 곳을 묻게 되지는 않는다
- 보정값은 어떤 기록이 쌓여도 상한과 하한을 벗어나지 않는다
- 답 없이 닫힌 횟수는 어떤 순서로 답해도 두 번 이상 남지 않는다

`app/`은 `settings.gradle.kts`에 적힌 Pleos Connect SDK 저장소에서 라이브러리를 받고, Pleos Connect 에뮬레이터에서 실행합니다.

## 에뮬레이터에서 확인한 것과 한계

- 확인함: 즐겨찾기 읽기, 경유지 넣고 빼기(넣고 약 6초 뒤에 다시 계산된 경로 값을 받음), 위치 이동(`adb emu geo fix`)과 영역 진입·이탈 알림.
- 한계: 에뮬레이터 내비게이션의 경로 값은 실제 도로 값이 아니어서, 도로 보정값 맞추기는 단위 테스트로만 확인했습니다. 실제 차량 신호(속도, 방향지시등, 착좌 등)는 엔진에 넣는 값의 형식(`DriveContext`)까지만 정했습니다.
