# 우회 시간 어림 비교 (공개 길찾기 경로 20건)

들를까는 경유지를 넣기 전에 "들르면 얼마나 더 걸리는지" 어림해 묻습니다. 그 어림을 공개 길찾기 엔진의 경로 값과 비교했습니다.

- 길찾기: OSRM 공개 데모 서버(`router.project-osrm.org`). 교통 정보가 없는 값입니다.
- 지도 자료: © OpenStreetMap contributors (ODbL). `raw/`에 받은 응답을 그대로 두었습니다.
- 한 경우는 지금 위치 A, 찜 P, 목적지 B로 이뤄집니다. A는 출발지에서 B로 가는 경로를 따라가다 P에서 직선 1.9km 안에 처음 들어온 지점입니다(앱의 찜 반경 2km 진입 직후).
- 실제 추가 시간 = (A→P→B 경로 시간) − (A→B 경로 시간)

## 비교한 식

| 식 | 내용 |
|---|---|
| V0 (처음 엔진) | (d(A,P) + d(P,B) − d(A,B)) × 1.3 ÷ 평균 속도. d는 직선거리, 평균 속도는 남은 거리 ÷ 남은 시간(하한 시속 20km) |
| V1 | max(0, t1 − s·T). t1 = A→P 경로 시간, T = A→B 경로 시간, s = max(0, d(A,B) − d(P,B)) ÷ d(A,B) |
| V2 (지금 엔진) | 2 × V1 |
| V3 | max(V0, V2) |

엔진에서는 t1을 내비게이션의 `requestTrip()`(경로 안내를 바꾸지 않고 그 지점까지의 거리·도착 예상을 돌려줌)으로 받습니다. 여기서는 OSRM의 A→P 경로 시간을 대신 썼습니다.

## 순서

1. 개발용 12건(시내 4, 국도 3, 해안 1, 산지 2, 고속도로 2)으로 V0를 쟀습니다(`route_check.py`). 경로 가까이 있는 찜일수록 V0가 0에 가깝게 잡혀 9건이 반올림해 0분(분을 빼고 묻는 경우)이었고, 실제보다 최대 17.7분 짧았습니다. 이 단계에서 찜 3곳(M1, H1, H2)은 붙은 길이 차로 들르는 길이 아니거나 공공장소로 보기 어려워 바꿔 다시 쟀습니다.
2. 그 결과를 본 뒤 V1~V3와 채택 기준을 정했습니다.
3. 수도권 밖의 검증용 8건(시내 2, 국도 2, 해안 1, 산지 1, 고속도로 2)을 어떤 어림·실제 값도 계산하기 전에 적어 두고 쟀습니다(`followup.py`). 찜이 길에서 200m 넘게 떨어진 경우는 없어 예비 2건은 쓰지 않았습니다.

채택 기준(검증용 8건): ① 반올림해 0분으로 잡았는데(분을 빼고 묻는 경우) 실제 2분 이상인 경우 0건, ② 고속도로를 빼고 실제보다 짧게 잡은 최대 차이 5분 이하, ③ 허용 10분 판정이 실제와 갈리는 경우 1건 이하. 셋을 모두 채우는 식 가운데 가장 단순한 것을 쓰기로 했습니다.

## 정한 것

세 식 모두 기준 ①을 NC2 한 건 때문에 채우지 못했습니다. NC2는 찜까지 가는 3.03분이 그동안 목적지 쪽으로 나아가는 몫(3.18분)보다 작아 0으로 나왔습니다. 미리 정한 대로라면 묻는 말에서 분을 빼야 했지만, 결과를 본 뒤 V2를 쓰기로 정했습니다. 판정(③)이 갈린 경우가 없고, 물을 만한 경우(V2 10분 이하)에서 말하는 값과 실제의 차이가 NC2를 빼면 1.1분 안이었기 때문입니다. 길게 잡은 NH1(+21.9분)은 묻지 않는 쪽이라 말을 거는 일이 늘지 않습니다.

## 한계

- 검증용이 8건뿐이고, V2의 최소 차이는 NH1 한 건이 정합니다. 고속도로 2건은 둘 다 광주대구고속도로입니다.
- 검증용 8건은 개발용의 경향(나들목으로만 드나드는 길에서 크게 틀림)을 안 상태에서 골랐습니다. 다만 어림·실제 값은 고르기 전에 보지 않았습니다.
- t1과 실제 추가 시간이 같은 길찾기 엔진에서 나오므로, V1·V2가 맞아 보이는 정도의 일부는 구조에서 옵니다. 실차의 `requestTrip()` 값의 단위와 실제 도로 값은 아직 확인하지 않았습니다.
- 교통 정보가 없고, 찜 좌표는 가장 가까운 도로에 붙인 어림입니다. P에서 U턴을 허용했습니다.

## 다시 돌리기

Python 3(표준 라이브러리만)이면 됩니다. 스크립트는 `raw/`의 응답을 먼저 쓰므로 인터넷 없이 같은 결과가 나옵니다.

```
python route_check.py   # 개발용 12건 → route_check_out.txt와 같은 표, results.json
python followup.py      # V0~V3 비교 → followup_out.txt와 같은 표, followup_results.json
```

V0 값은 엔진 소스를 따로 컴파일해 같은 입력으로 돌린 값과 최대 4.6e-11분 안에서 같았습니다. 엔진의 V2는 `engine/src/test/.../DetourEstimatorTest.kt`가 NC1·NC2·NH1의 값을 그대로 맞추는지 확인합니다.
